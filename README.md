# AutoPDF 2

### モバイル再生

PCで `ollama pull qwen3.5:2b` を一度実行し、「難しいページだけQwenで判定」を
有効にします。図表番号、列状の文字配置、スキャン画像の濃い領域を手掛かりに、
候補ページだけを推論します。解析結果は合成前にプレビューで修正できます。

変換後の `.autobook` を端末のローカルストレージにコピーし、プレイヤーの
「AutoBookを開く」から選びます。本文をタップするとその区間から再生します。
新規書籍はMP3を収録します。アプリはモデルやサーバー接続を必要としません。
GitHub Actions の AutoBook mobile がAndroid用のABI別APKとiOS署名前のビルドを
生成します。iPhoneへの配布にはAppleの署名が必要です。

Windows上の文書ビューアを自動撮影してPDFにする機能と、PDFから文字を抽出して
Style-Bert-VITS2でWAV音声を作る機能を1つのGUIにまとめたツールです。

既存の `autoPDF.py`、`folderToPdf.py`、`mousePointer.py` はそのまま残しています。
新しい実装の入口は `autopdf_app.py` です。

## セットアップと起動

1. `setup_autopdf.bat` をダブルクリックしてPython依存パッケージを導入します。
2. `start_autopdf.bat` をダブルクリックします。

画像だけのPDFを読む場合は、別途Tesseract OCRと日本語言語データが必要です。
Windows版Tesseractを導入し、GUIの「Tesseract」欄で `tesseract.exe` を指定してください。
横書きはOCR言語 `jpn`、縦書き用言語データも導入した場合は `jpn_vert` または
`jpn+jpn_vert` を指定できます。

## スキャンからPDF

ログイン済みのChromeでは、DevToolsのデバイス表示を希望のサイズに整えたまま、「Chrome高解像度スキャン」→「開いているタブ」を使います。
「スキャン→PDF」でページ送りの操作列を選び、Chromeタブで資料名、撮影枚数、手動撮影したPNGと同じ画素数を指定します。
Chromeのダウンロード先を選び、保存場所を毎回確認する設定はオフにします。DevToolsの空白と閲覧ページ内の余白をオーバーレイで指定します。
DevToolsのコマンドメニューで英語の Capture screenshot が選択できる状態で開始してください。
最初の画像を確認して続行すると、設定した操作列でページをめくり、指定枚数をPDFにまとめます。
撮影中はウィンドウの配置を維持してください。中断後は同じ資料名で再開できます。

「A4へ整形」では、撮影した画像の縦横比を保ち、A4ページに収まる最大サイズで配置します。細かい文字を鮮明に撮るには、閲覧アプリで本文を拡大してから撮影範囲を指定してください。

1. 文書を表示した状態で「画面上で撮影範囲を選択」を押し、画面上で範囲をドラッグします。既存範囲はオレンジの点線で表示されます。Escでキャンセルできます。
2. ページ数、開始待機、出力先を設定します。
3. ページめくり手順を作ります。
   - Kindleの標準例は `right` キーと0.2秒待機です。
   - キー、クリック、ドラッグ、スクロール、待機を任意の順番で組み合わせられます。「クリック追加」では、画面上の十字を対象ボタンに合わせて F8 を押すと位置を登録できます。
   - 「1回分を記録」では、実際に1ページめくってF8を押すと操作を記録します。
4. 「手順をテスト」で1回だけ再生し、正しくめくれることを確認します。
5. プロファイルを保存して「スキャン開始」を押します。

画像は出力先のPDF名と同名のサブフォルダへ保存され、最後にPDFへまとめられます。
画面が変化しなかった場合は同一ページと判断して停止できます。誤停止する場合は
「重複判定(%)」を小さくするか、判定をオフにしてください。緊急時はPyAutoGUIの
フェイルセーフとしてマウスを画面左上へ移動するか、GUIの停止ボタンを押します。

## PDFからStyle-Bert-VITS2音声

1. Style-Bert-VITS2側で `server_fastapi.py` を起動します。既定URLは
   `http://127.0.0.1:5000` です。
2. PDF、出力先、ページ範囲を指定します。
3. 抽出方法を選びます。
   - `auto`: PDFのテキスト層を使い、文字がほぼないページだけOCRします。
   - `text`: テキスト層のみ使います。
   - `ocr`: 全対象ページをOCRします。
4. 「読み上げ除外」で表、画像・図内文字、図表キャプションを選びます。
   - テキストPDFでは表と埋め込み画像の座標に重なる文字を除外します。
   - 画像PDFではOpenCVで罫線表を検出し、白塗りしてからOCRします。
   - 図中文字まで高精度に避けたい場合はOllamaを起動し、「Ollamaで本文判定」を
     有効にして視覚モデルを選択します。Ollamaは任意機能です。
5. 「接続・モデル取得」を押し、Style-Bert-VITS2のモデル・話者・スタイルを選びます。
6. 「PDF解析」で抽出内容を確認します。プレビュー内の本文は修正できますが、
   `=== 1ページ ===` のようなページ見出しは残してください。
7. 「音声合成開始」を押します。

公式APIの既定入力上限は100文字なので、初期値は90文字ずつに分割します。各音声は
`chunks` に残り、最終的に `<PDF名>_audiobook.wav` へ連結されます。同じフォルダに
読み上げ本文 `transcript.txt` と処理条件 `manifest.json` も保存されます。
さらに、圧縮音声・表紙・本文・ページ位置をまとめたAndroid転送用
`<PDF名>.autobook`を自動作成します。Androidへコピーした後はPCを起動しておく
必要はありません。

## 注意事項

- Style-Bert-VITS2本体、学習済みモデル、GPU環境はこのリポジトリには含みません。
- OCR品質は元画像、フォント、縦横書き、Tesseract言語データに左右されます。
- 罫線のない表や複雑な図の判定は完全ではありません。音声化前にプレビューを確認し、
  必要なページだけOllama判定を使うと処理時間を抑えられます。
- スキャンや音声化は、利用者が閲覧・複製・変換する権限を持つ文書だけに使用して
  ください。このツールはDRMやアクセス制御を解除しません。
- ページめくり記録と再生は実際のマウス・キーボード入力を送ります。必ず少ない
  ページ数で試してから長時間処理を始めてください。

## Android版の方針

Android版はPCサーバーを使いません。高品質版はPCで一度だけStyle-Bert-VITS2音声を
生成してAutoBookを転送し、その後はAndroidだけでオフライン再生します。Android単体で
新しいPDFを読む場合はML Kit日本語OCRとAndroid標準TTSを使います。詳細は
`ANDROID_ARCHITECTURE.md`を参照してください。
